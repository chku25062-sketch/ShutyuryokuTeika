# 機能仕様書：生成AIによる問題自動生成・ストックシステム（無料運用設計）

## 1. 概要・目的
集中力測定において、同じ問題の繰り返しによる「学習効果（記憶で即答してしまう現象）」を完全に防ぎ、常に初見の高品質な問題（特に文章読解・タイピング）を供給するための自動生成システム。
利用料金を一切発生させず（**完全無料**）、かつオフラインでも快適に受検できるアーキテクチャを定義する。

---

## 2. 無料実現性の検証（コストゼロの根拠）

### 2.1 利用API：Google Gemini API（Gemini 2.0 Flash / 1.5 Flash）
- **無料枠（Free Tier）スペック**:
  - リクエスト数制限: **1,500 回 / 日**（15 RPM）
  - トークン制限: 100万 トークン / 分
- **本アプリでの想定消費量（30分に1回のバッチ生成）**:
  - 1日 = 24時間 × 2回 = **48回 / 日**
  - **無料枠のわずか約3.2%のみ消費**（残り1,452回/日の余裕）。
  - クレジットカード登録不要、または無料枠上限ロックにより、追加課金リスク0で運用可能。

---

## 3. 実装アーキテクチャ案

### 案A：GitHub Actions 定期実行 × クラウドストック（完全自動化）
1. **トリガー**: GitHub Actionsの定期Cron（`cron: '*/30 * * * *'`）が30分ごとに起動（パブリックリポジトリでのCron実行は完全無料）。
2. **生成**: スクリプトがGemini APIを呼び出し、読解・タイピング・暗記問題を各2〜3問生成。
3. **ストック**: Supabase（無料プラン）またはリポジトリ内JSONに最新問題プールとして蓄積。
4. **配信**: アプリ起動時に最新ストックを取得してローカル（IndexedDB）にキャッシュ。

### 案B：クライアント自動補充＆ローカルストック（オフライン完全対応・推奨）
1. **残量検知**: ユーザーがアプリを利用中、ブラウザ内（LocalStorage / IndexedDB）の未出題問題ストック残量を監視。
2. **バックグラウンド補充**: 残量が3問以下になった際、オンライン状態であれば裏でNext.js Route Handler経由でGemini APIを呼び出し、5〜10問を一括自動補充。
3. **オフライン受検**: 事前に端末内に常に5〜15問がストックされているため、ネット未接続時でも初見の生成AI問題を即座に受検可能。

## 4. 生成プロンプトとJSONスキーマ定義（Structured Outputs）

### 4.1 文章読解問題（Reading Comprehension）
```json
{
  "type": "object",
  "properties": {
    "category": { "type": "string", "enum": ["reading"] },
    "passage": { "type": "string", "description": "100〜150文字程度の短文（時事・科学・日常・論説など多岐にわたる）" },
    "question": { "type": "string", "description": "本文の論理的整合性を問う設問" },
    "options": {
      "type": "array",
      "items": { "type": "string" },
      "minItems": 4,
      "maxItems": 4,
      "description": "4択の選択肢"
    },
    "correctIndex": { "type": "integer", "minimum": 0, "maximum": 3 }
  },
  "required": ["category", "passage", "question", "options", "correctIndex"]
}
```

### 4.2 タイピング問題（Typing Text）
```json
{
  "type": "object",
  "properties": {
    "category": { "type": "string", "enum": ["typing"] },
    "japaneseText": { "type": "string", "description": "入力対象の自然な日本語文（40〜60文字）" },
    "romajiText": { "type": "string", "description": "対応するローマ字表記（ヘボン式・訓令式互換用）" }
  },
  "required": ["category", "japaneseText", "romajiText"]
}
```

## 5. 自動補完事項・設計方針（AI補完と合意形成ルールに基づく）

> **[自動補完内容]**:
> 1. **段階的導入計画**:
>    - 第9回・第10回：乱数・テンプレートによる「完全オフライン動的生成」を土台とする。
>    - 第12回〜第14回：Gemini API連携モジュールを導入し、バックグラウンドでのAI問題ストックを有効化する。
> 2. **フォールバック保証**:
>    - APIエラーやネットワーク切断時でも、即座にオフライン用アルゴリズム生成（乱数計算・テンプレート文章）に自動で切り替わり、測定が絶対に中断しないセーフティネットを設ける。
